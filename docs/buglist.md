- [x] Color Gradient does not work as intended. When switching to gradient no matter what color is selected it defaults back to black. Then changing that the "to" color is set to black. When changing that the "from" color goes back to black.
  - Fixed. Every control in the matte panel was editing a copy of the fill taken when the panel was built, and the swatches deliberately do not rebuild the panel, so each edit wrote a stale copy back over the last one. They now read the matte as it stands. The panel heading followed the old colour too, and now does not.
- [x] Docked windows not behaving as expected. Dragging to side sometimes does not dock the window. Especially noticable when multiple items are tabbed together. Also seems to be impossible to drag tab to separate window.
  - Fixed, three faults. A tab that was not already showing could not be dragged at all: pressing it asked for it to be shown, showing it rebuilt the tree, and the rebuild destroyed the strip holding the press. The gesture now lives in the dock view, which survives the rebuild. That is the "especially when multiple items are tabbed together" one — in a group of several, most tabs are not the one showing.
  - A tab dragged clean out of every window could not become a window of its own: the drop zone and the drag were one piece of state, so telling the window "there is no zone to draw here" also made it forget what was being carried, and the release did nothing.
  - And the side rims lost to any tab strip at the same height, so aiming a panel at the very edge of the window joined a tab group instead. The left, right and bottom rims now win; the top rim still yields, because the topmost strip runs its whole length and would otherwise be untabbable.
- [x] While video preview is playing the user is unable to adjust the volume slider on the audio tracks
  - Fixed, and it was every drag on the timeline rather than only that one. Each gesture there is a live edit of the view's own model — that is what makes a trim, a move or a volume band visible while it happens — and the playback loop rebuilds that model once per displayed frame. So a drag during playback had the thing it was editing replaced sixty times a second. The volume band is where anybody would notice, because it is the one you hold still while listening. A model handed over mid-gesture now waits until the gesture ends rather than being applied or thrown away.
- [x] The user is unable to scroll on the timeline while the video is playing
  - Fixed. Following the playhead runs on *every frame* of a playback, and it moved the view whenever the playhead was not comfortably inside it — so the wheel moved the view and the very next frame put it straight back. Nothing was wrong with the scrolling; it was being undone faster than it could be seen.
  - A view scrolled by hand is now left where it was put, and following resumes on its own once the playhead reaches what is on screen — so looking ahead at what is coming is something you stop doing without having to press anything. Pressing play hands the view back deliberately, since that is a statement about what is being watched.
- [x] Application crashed when adjusting preview quality while project was playing
  - Fixed. Changing the quality changes the canvas the preview renders at, and the preview answers a new canvas size by throwing its whole renderer away and building another — it owns a compositor and every open decoder, all sized to the old one. What it did not do was wait for the graphics card to finish first. The texture being freed is the one the monitor is drawing, so the frames still in flight referred to memory that had just been returned; that removes the device, which arrives as the window dying. Only while something is drawing continuously, which is to say: while the sequence is playing.
  - Two more of the same fault were found beside it and are fixed too. The monitor now lets go of the picture before any render that will change the canvas underneath it, since the code that resizes is not always the code that hands back a replacement — the scopes and the snapshot both rendered at a size the monitor had not asked for. And the scopes were asking for the sequence's *own* size while the monitor was showing a reduced one, so at any quality below Full every single frame rebuilt the compositor twice. They measure the picture on screen now, which is both cheaper and what a scope is for.
  - The guard meant to catch exactly this could not. A texture carries a generation so that a caller can tell a rebuilt one from the one it was given — addresses get handed straight back out — but the count started at zero in each compositor, and a resize builds a *new* compositor. The replacement handed back generations its predecessor had already used, so a stale handle compared equal to a live one. The count is now shared by every compositor in the process and never restarts.
- [x] Not able to dock a window to a section that it was already docked to (For example: if two panels are docked to the left side you are unable to drag one panel to the bottom of that and dock it. You first have to dock it elsewhere and then you can drag it back)
  - Fixed. A drop names the panel it landed on, and what a tab group offers is whichever tab is *showing* — which, while one of its own tabs is being dragged, is the panel being dragged. So "put this down the bottom of the group it is in" arrived as "dock A beside A" and was turned away by a guard meant to stop a panel being dropped on itself pointlessly. The drop zone was drawn the whole time, which is why it looked like it should work.
  - It is answered against one of its neighbours now, which names the same group and needs nothing else to change. Dropping a panel on itself in the *middle* still does nothing, because it is already there and already showing, and so does an edge drop by a panel that is alone in its pane — that would split a pane off itself and leave the same pane.
- [ ] I noticed a bug with the freedraw mask. It's not really free draw like in premiere where you have bezier curves you can move and manually draw a shape. It is just a rect that you can move the corners on. It also had issues when I had a mask in freedraw and then changed it to elipse and rectangle
  - The second half is fixed. A path lives entirely in its corners, and the half-extents — which are the ellipse's radii and half the rectangle's sides — were left at whatever they happened to be before anything was drawn. Pulling the corners about never touched them. So switching that mask to Ellipse or Rectangle produced a shape with no relation to the outline that had just been on the picture, because the two were never describing the same thing. The extents now follow the corners, so all three shapes mean the same region: an ellipse switched to from a path lands inside the outline that was there, and switching back gives corners that still match the box.
  - The first half is not a bug and is not fixed: it is a feature that was never built. Free Draw is a polygon of four corners you can drag, and there is no way to add a corner, remove one, or curve an edge. The model already carries up to sixty-four points and the shader already fills any polygon, so what is missing is the pen: clicking to place corners, dragging a handle out of one to bend the edges either side, and closing the path. Bezier means a control point either side of every corner in the model, a flattening step before the shader (which fills straight edges and should keep doing so), and a monitor that can draw and hit-test handles as well as corners. That is a section of its own rather than a fix, and it is written up in the gaps document rather than here.
